# 软件工厂项目章程（设计基线）

## 1. 使命

建设一个以共享领域语义、经过批准的软件资产和可验证交付为核心的可组合软件工厂参考实现。首个场景是围绕已批准的 Kafka 版本进行标准化配置、客户化配置、真实校验与候选配置交付，不重写 Kafka 本身。

## 2. 业务问题

不同 Agent 与工程平台可能对“需求已完成”“构建成功”“版本兼容”“可发布”等状态采用不同含义；客户化差异容易污染标准版本；生成结果可能缺少真实测试、安全与来源证据。项目需通过语义契约、显式工作流、受控工具、独立门禁和审计链解决这些问题。

## 3. 目标

- 结构化需求与明确验收条件；
- 只复用已批准且版本明确的资产；
- 执行真实、可复现的配置校验/测试；
- 将结果绑定到版本、运行、报告和制品摘要；
- 门禁失败时阻止交付；
- 高风险发布经过独立授权与人工审批；
- 可测量质量、返工、延迟、人工介入和成本。

## 4. 非目标

- 自主重写 Kafka 或通用中间件；
- 任意软件的完全自主开发；
- 默认生产写权限或无限制 Shell；
- 取代 Git/CI/安全扫描/制品库/部署平台；
- 将本体字段当作授权系统；
- 在没有真实凭据/执行环境时宣称外部集成通过。

## 5. 关键利益相关方

产品/交付负责人、领域专家、架构师、平台工程师、开发与测试工程师、安全人员、发布审批人、运维人员。

## 6. 交付与决策原则

每个能力都必须有负责人、稳定接口、验收标准、负向测试和失败恢复方案。架构改变应通过 ADR；目标状态只有在证据满足后才能从 PLANNED 改为 PASS。

## 7. 成功衡量

任务成功率、实际测试通过率、门禁正确阻断率、缺陷逃逸、人工介入/返工、端到端时延、单位成功交付成本、证据追溯覆盖率。
