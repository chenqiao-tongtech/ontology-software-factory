# 端到端流程：从需求到交付证据

```mermaid
flowchart TD
    R[需求输入] --> S[结构化与范围检查]
    S --> A[选择已批准资产与版本]
    A --> C[生成/修改配置或代码]
    C --> B[隔离构建]
    B --> T[真实测试]
    T --> Q[质量与安全门禁]
    Q -->|失败| F[记录证据并生成修复任务]
    F --> C
    Q -->|通过| P[生成候选交付制品]
    P --> H{需要人工审批?}
    H -->|是| HA[人工审批]
    H -->|否| D[受控交付阶段]
    HA -->|批准| D
    HA -->|拒绝| STOP[停止并保留原因]
    D --> V[交付验证与交付记录]
    V --> O[运行反馈/改进需求]
```

## 关键控制点

1. 需求不清晰时，回到范围确认，不让 Agent 自行补出未经确认的业务约束。
2. 资产版本没有批准状态或来源信息时，不能进入生成阶段。
3. 构建/测试命令运行于隔离 runner，不能直接继承个人开发机或生产凭证。
4. 失败路径必须记录失败类别、证据和下一步动作；重试次数有上限。
5. 门禁结果绑定到正在评估的 commit 与制品摘要，不能拿旧报告证明新制品安全。
6. 生产执行权限由身份/策略系统控制，不能由 Agent 在对话中“申请后自动放行”。
