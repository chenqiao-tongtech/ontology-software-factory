# 架构设计原则与不可绕过的约束

## 原则

1. **资产优先、集成优先**：优先采用批准资产和成熟 Git/CI/扫描/制品平台，自建差异化语义与跨工具治理。
2. **共享语义、适配器隔离供应商差异**：模型、Agent 框架、工具平台可换，核心对象含义和契约不跟着变。
3. **控制面与执行面分离**：规划/编排负责创建有界任务，Runner 负责按已批准规范执行。
4. **生成与验证分离**：模型生成候选物；独立工具产生真实验证证据。
5. **默认拒绝、最小权限**：工具必须显式注册并按角色、操作、资源、风险授权。
6. **高风险动作独立审批**：生产部署、删除、数据迁移、权限更改和秘密轮换不得由 Agent 自行放行。
7. **标准资产与客户配置分离**：配置覆盖和客户补丁应可追踪、可重放、可升级。
8. **证据驱动、可追溯**：每项关键结论关联源版本、运行 ID、退出码、日志/报告、制品摘要与审批。
9. **失败可解释、状态可恢复**：统一错误码、幂等键、重试、超时、取消、补偿和未知结果对账。
10. **渐进实施、可替换技术**：先用最小依赖跑通关键链路，扩展须有明确的业务理由和退出条件。
11. **本体受版本治理**：词汇和关系变化需要 owner、影响分析、迁移策略、回归测试与批准。
12. **效果必须基于基线测量**：同一测试集和质量门槛下比较人工与 Agent 方案，不预设必然提效。
13. **多智能体协作显式化与可控**：团队拓扑、顺序/并行关系、交接契约、共享上下文边界、独立复核和修复上限必须配置化；确定性 Workflow 控制派发和状态，Agent 不自授权、不审批自己的高风险结果。

## 硬约束

- C-01 Kafka 是贯穿示例，不是需要重写的项目。
- C-02 本地 MVP 不执行真实生产部署。
- C-03 不提供无限制 Shell、任意网络和默认生产凭证。
- C-04 模型生成的文字声明不能代替工具日志与真实报告。
- C-05 缺少必要安全证据时 fail closed。
- C-06 本体不独立授予权限，IAM/策略引擎负责授权。
- C-07 外部服务和凭据不可用时明确标记未验收。
- C-08 改变边界需更新 MVP、设计基线、验收项和 ADR。
- C-09 多智能体必须采用有界拓扑和版本化 Handoff；关键证据冲突、循环耗尽或审批异常必须停止或升级人工。

## 每次设计评审的问题

- 解决什么业务问题？为什么现有工具/模块不够？
- 输入、输出、稳定 ID、Schema 版本和错误语义是什么？
- 是否引入外部依赖、数据、权限、副作用、成本或运维责任？
- 失败如何重试、对账、回滚或交由人工处理？
- 用哪条自动化正向/负向测试证明正确？
- 当前实现状态是否准确标记为 planned/partial/implemented？


## AP-14 主控规划受控

Factory Orchestrator 只负责生成有界、结构化的 AgentPlan。Workflow Engine 对计划进行 Schema、依赖、角色、Skill、预算和策略校验，并拥有任务创建、状态转换、重试和暂停恢复的权威性。Agent 不得自行修改权威状态或授予权限。

## C-10 主控权限边界

Factory Orchestrator 不直接派发任务、不修改 Workflow 状态、不授予工具权限、不批准自身计划、不发布正式本体。高风险操作由独立策略和人工审批流程决定。
