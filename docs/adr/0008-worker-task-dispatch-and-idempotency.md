# ADR-0008: Worker 任务派发、租约与幂等键

- 状态：Accepted for MVP reference
- 日期：2026-10-27
- 关联：ADR-0007 工作流状态机与控制台

## 背景

第 19 篇定义的是工作流运行和节点状态，但“节点运行中”本身不代表有一个可靠的外部 Worker 执行任务。需要将派发、执行租约、尝试次数、失败策略与证据写入独立契约。

## 决策

1. 增加独立的 SQLite 任务存储，原子完成入队、领取、结果持久化和事件追加。
2. 使用入队幂等键，阻止同一任务请求被重复创建；同键、不同负载失败关闭。
3. 使用租约 fencing：只有租约当前持有者可以提交结果。
4. 自动重试仅接受显式白名单中的错误类别，并限制尝试次数与退避上限。
5. 成功结果必须通过证据契约；真实 Handler 必须返回真实制品 URI 和实际内容哈希。
6. 不声称 exactly-once；远端副作用必须用稳定业务操作 ID、下游幂等或对账来控制。
7. 任务队列与 Workflow Run 不在同一事务中，工作流回写必须使用 outbox/reconciler 或可重放回调。

## 后果

- 好处：职责分离、可测试、适合从本地 MVP 向托管 Worker 演进。
- 代价：需要处理队列状态与工作流状态的跨系统一致性；SQLite 不能替代高可用队列。
- 风险：租约保护队列状态但无法阻止旧 Worker 已经发出的外部副作用，因此业务幂等仍然必需。
