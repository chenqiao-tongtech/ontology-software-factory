# ADR-0001：首版优先打通受控的最小交付闭环

- 状态：Accepted（本系列参考实现的设计决定）
- 日期：2026-10-27

## 背景

“软件工厂”容易被误解为让 Agent 自主生成任意软件并直接上线。该目标过宽，无法在第一阶段验证语义契约、工程执行和质量治理是否可靠。

## 决策

首版围绕一个边界清晰的中间件交付案例：引用已批准版本，生成/验证配置，真实运行构建和测试，执行质量门禁，形成可追踪交付记录。生产发布保留人工审批。

## 备选方案

- A：以通用自主编程 Agent 为中心，先追求全自动开发。
- B：以标准资产、明确需求、真实工具执行和质量门禁为中心，逐步增加 Agent 自主性。

选择 B。

## 后果

- 优点：范围可验收、风险可控，能够逐篇增加真实能力。
- 代价：首版自动化范围较窄，部分步骤需要人工完成或确认。
- 后续复审条件：当构建、测试、权限、审计和恢复能力有可复现的验证证据后，再考虑扩展自动化范围。
