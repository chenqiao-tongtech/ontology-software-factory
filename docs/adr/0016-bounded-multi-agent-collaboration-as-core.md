# ADR 0016：将有界多智能体协作作为软件工厂核心架构

- 状态：Accepted（设计基线）
- 日期：2026-10-29
- 关联：第 15 篇总体架构、S4 多智能体协作、S5 Workflow、C-09

## 背景

仅列出 Agent Roles 和 Skills 不能说明它们如何组成生产团队。若不提前定义拓扑、交接、并行汇合、上下文边界、独立验证和修复上限，后续实现容易变成自由对话，造成重复执行、权限边界不清、证据冲突和无法复现。

## 决策

1. 将 S4 定义为“多智能体协作与 Agent 能力”，与 Workflow 状态机 S5 分离。
2. MVP 使用确定性 Workflow 控制器调度专业 Agent；它决定派发、Join、重试与审批门，LLM 不拥有权威状态。
3. Agent 间通过版本化 AgentHandoff 契约交换对象/制品/证据引用，并明确上下文范围、工具、期限、预算和验收条件。
4. 候选产物快照冻结后，测试 Agent 和安全审查 Agent 独立并行；Quality Gate 采用 all-required 规则。
5. 修复循环最多 2 次；关键分歧、证据缺失、预算/期限耗尽或审批拒绝时升级人工或停止。
6. Agent 不得扩展自身工具权限、直接修改 Workflow 状态或批准自己的高风险结果。

## 备选方案

- 开放式 Agent 群聊：拒绝，状态、成本和故障难以界定。
- LLM Supervisor 独立决定所有步骤：不作为 MVP 的权威协调器；模型可以提出计划，但生产顺序由 Workflow 执行。
- 所有任务严格顺序：可作为简单流程，但不能覆盖测试/安全证据的独立并行收集。
- 多个顶层 Workflow 框架同时控制同一状态：拒绝，避免双重权威状态。

## 后果

增加 Team Topology、AgentHandoff Schema、协调器验证和负向测试。真实 Agent Runtime 的运行路由尚需接入该拓扑，当前状态标记为 partial；拓扑配置校验通过不代表生产级多 Agent 执行已完成。
