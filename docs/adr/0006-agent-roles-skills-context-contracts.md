# ADR-0006：将 Agent 岗位、Skills、工具与上下文分别建模

- Status: Accepted for the Article 18 reference implementation
- Date: 2026-10-28

## Context

如果只用一段提示词表示 Agent，职责、工具权限、上下文边界和验收要求会混在一起，难以审计、复用和测试。多个 Agent 可能使用相似工具，但其可写入对象、输出类型和人工审批要求不同。

## Decision

1. Role 作为责任边界，分别记录输入/输出实体类型、Skills、工具白名单、允许/禁止动作、上下文分类、交接要求和升级条件。
2. Skill 作为带版本的能力包，定义兼容角色、输入/输出实体、所需工具、成功标准、失败条件、上下文要求及副作用边界。
3. 工具统一在 `agents/tool-catalog.json` 注册，标注风险、副作用、审批要求和 MVP 可用性。
4. 任务和结果采用机器可验证 Schema，状态、证据、失败原因和人工复核标记使用受控字段。
5. 上下文分为共享任务、角色局部和受限上下文；外部文档和工具输出均视为不可信数据。
6. 生产部署、受保护分支合并、读取秘密明文、修改策略和 Agent 自行审批在 MVP 中全局禁止。
7. 独立的 IAM/策略执行点必须在每次工具调用时重新鉴权；这些定义文件只是声明式输入，不是运行时安全边界。

## Consequences

- Role/Skill 更容易做版本化、差异比较和自动验证。
- 新增 Skill 若需要当前 Role 未授权的工具，必须先审核角色权限，不能静默扩权。
- 运行时需实现身份注入、策略判定、沙箱、日志和人工审批；本次不实现 LLM 调度或真实工具执行。
- 高影响动作采取独立审批，审批主体不能与发起主体相同。
