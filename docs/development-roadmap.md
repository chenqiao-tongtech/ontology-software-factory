# 软件工厂开发路线图与阶段门

| 阶段 | 对应篇目 | 主要内容 | 退出条件 / 证据 |
|---|---|---|---|
| P0 规划与概要设计 | 15 | 项目章程、总体架构、模块拆分、本体路线、约束、开发计划 | 设计基线校验通过，范围/接口/依赖/非目标可追踪 |
| P1 语义与契约 | 16 | 领域词汇、核心 Schema、语义一致性和样例 | Schema 正负向测试，跨对象错误可被拒绝 |
| P2 资产目录 | 17 | 资产元数据、版本/依赖、客户配置和兼容性 | 目录正负向测试，未验证项不伪装兼容 |
| P3 多智能体协作与 Agent / Skills | 18 | Team Topology、Role、Skill、Handoff、上下文范围、并行验证和独立复核 | 未知角色/非法交接被拒绝，独立验证汇合且循环上限生效 |
| P4 工作流 | 19 | DAG、状态机、超时、重试、暂停/恢复、审批 | 转换非法时阻断，事件重放和恢复测试通过 |
| P5 工具/安全执行 | 20 | MCP/API/Git/CI/Runner 接入、权限、沙箱边界 | 工具契约、默认拒绝、超时/幂等和审计验证 |
| P6 真实生产流水线 | 21 | 选择资产、生成配置/变更、执行校验/测试、记录证据 | 从请求到候选交付可重放，失败可观测 |
| P7 质量与安全门禁 | 22 | 测试、SAST/SCA、秘密/许可证扫描、豁免和门禁 | 故意引入问题时门禁阻断，报告绑定版本/摘要 |
| P8 发布与回滚 | 23 | 发布清单、审批、配置、健康验证、升级/回滚 | 审批和失败回滚演练有实际日志 |
| P9 观测与生命周期 | 24 | 指标、用量/成本、审计查询、本体/流程变更 | 可以对照人工基线报告质量、成本、时延和返工 |

## 计划约束

- 每阶段均需定义输入、输出、依赖、测试和可验收证据。
- 前一阶段的文档完成不等于后续能力完成；技术实现状态独立记录。
- P1–P4 可逐步并行开发，但跨模块契约需先稳定版本。
- 多智能体协作采用“确定性 Workflow 控制器 + 专业 Agent”模式；团队拓扑、交接契约、并行汇合及循环上限是第 15 篇设计基线的一部分，不是后续自由添加的可选功能。
- P5 先只读工具，再按风险等级开放写权限；所有高风险写操作需要审批。
- P6 先以配置交付为最小纵向切片，不承诺构建 Kafka 二进制。
- P7 的缺失扫描器/报告必须导致 incomplete/block，不允许默认为 pass。
- P8 在本地 MVP 只演练状态与配置回滚；接真实集群前需额外的安全和变更评审。
- P9 的成本没有可靠价目表时标记未知，不能估成零。
