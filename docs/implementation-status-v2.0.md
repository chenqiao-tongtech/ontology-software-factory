# v2.0 正式编号与工程补充篇对齐说明

此前会话中第 20–24 篇曾按工程补充路线编写为 Worker 可靠派发、Outbox/Inbox 闭环、真实 LLM Adapter、Agent Runtime 和多 Agent 提案流水线。这些材料有价值，但与 v2.0 正式目录原定编号不一致。为避免丢失已完成工作，本仓库采用双轨归档：

- `article/通往AI之桥_本体论系列20～24_公众号发布稿.md`：正式对齐 v2.0 的文章，分别为工具与安全执行、第一条流水线、质量安全门禁、发布升级回滚、观测成本与生命周期。
- `article/supplementary/`：之前已写的 Worker、事件闭环、LLM、Agent Runtime、多 Agent 文章作为工程补充篇保留，不再占用正式 v2.0 篇号。

补充篇的代码仍保留在项目中，并继续接受测试。正式第 20–24 篇新增的代码和验收内容也在同一代码库内。

## 不应宣称已完成的生产能力

- 真实 Kafka binary 下载、来源证明和兼容测试；
- 容器/微虚机级沙箱；
- Trivy/Gitleaks 扫描仅在工具安装后扫描候选配置目录；当前环境缺少扫描器，因此生产 Gate 阻断。源代码 SAST/SCA、Kafka 二进制/容器扫描尚未接入；
- Git 分支/PR 和实际代码变更应用；
- 真实 Kubernetes/Kafka 部署和生产回滚；
- 完整的多租户生产观测后端、财务账单与审批系统。

这些能力应在提供必要工具、环境、授权与凭据后另行接入，不能用单元测试或配置示例冒充。

## 第 15 篇规划设计基线更新（2026-10-29）

第 15 篇已经重新定位为总体规划与概要设计篇，并新增机器可读 `config/architecture-baseline.json`、11 个子系统的模块/组件责任分解、非功能要求、技术选型与替代方案、首版风险登记、本体设计与演进方案、阶段门路线图和 Mermaid 图源。

验证：`python scripts/validate_architecture_baseline.py`、`make validate`；新增架构基线测试覆盖 ID 唯一性、依赖缺失/循环、实现路径、路线图退出条件和必需设计文档。该验收表示设计资产内部一致，不将计划中的外部集成或生产能力标为完成。

## 第 15 篇多智能体架构修订（2026-10-29）

多智能体协作已进入第 15 篇总体架构基线：增加 S4 核心子系统、机器可读 Team Topology、AgentTeam/AgentHandoff 等操作域扩展、交接 Schema、独立验证并行 Join、循环上限与 ADR 0016。当前配置/契约/校验已本地测试通过；将拓扑实际连接到 Agent Runtime 和生产级调度仍标记为 partial，不能以设计校验代替运行时验收。
