# 七项本体发现与图谱工作台能力验收矩阵

日期：2026-10-30

本文件把本轮七项工作映射到当前代码，避免将已存在的能力重复建设，也避免把本地参考实现描述成生产集成。

## 能力矩阵

| # | 能力 | 当前实现 | 验收边界 |
|---|---|---|---|
| 1 | GitHub / GitLab 统一连接器 | `SourceConnector` / `SourceConnectorRegistry` 协议；`RemoteRepositoryConnector` 以 GitHub.com、GitLab.com 元数据扫描实现同一 `scan` 接口；Portal 显式同步时调用注册表 | 仅扫描仓库元数据与文件路径，不下载文件正文；仅公共托管域名；无自托管实例、Webhook 或增量游标 |
| 2 | PostgreSQL / MySQL 只读结构发现 | `PostgreSQLSchemaConnector`、`MySQLSchemaConnector` 读取命名环境变量中的 DSN，并查询 `information_schema` | 可选驱动；要求主机 allow-list 与 TLS；应用层 allow-list 不是网络出口防火墙；需要真实环境做驱动、权限、证书和网络验收 |
| 3 | 本体证据链 | 候选术语 evidence 保存 source identity、locator、asset ID、revision、content digest（可用时）与扫描时间；证据有效性检查支持内容/Schema/版本变化状态 | 远端文件正文不下载，不能伪造内容哈希；数据库只保存 schema locator，不采集业务行；本地同步历史不是不可篡改审计日志 |
| 4 | 本体版本 Diff | 显式快照、规范化 JSON SHA-256、类/关系/词汇/不变量差异；Portal 提供快照创建和比较 | 快照在本地 Portal 状态中，不是签名制品或防篡改注册表；当前不提供一键回滚正式文件 |
| 5 | 来源追踪 | 候选证据详情展示来源、路径、asset ID、revision、hash、扫描时间；远端文件提供经过 host 校验的浏览器链接 | 本地文件仅展示路径与 hash；数据库证据只到表/字段元数据；远端链接指向默认分支，需结合 revision 审查 |
| 6 | 变更影响分析 | 结构 Diff 推导受影响概念；依赖图可查询 Agent Role、Skill、Workflow、Tool、Contract 对本体概念的引用 | 不存在引用索引时不推断消费者；本体结构影响与下游消费者影响分开报告；兼容性检查不等于自动迁移 |
| 7 | 交互式图谱审查 | Portal SVG 图谱支持节点搜索、概念选择、出入关系查看；本次补充关系边选择与关系详情 | 当前为本地 Portal 的 SVG 视图，不是独立部署的图数据库工作台；布局是确定性演示布局，不支持大图性能优化、多人协作编辑或实时推送 |

## 关系边交互修复

正式本体关系定义使用 `name` 作为关系标识，并未定义 `id`。图谱此前把不存在的 `id` 写入 SVG 的 `data-edge`，导致关系边无法稳定映射回关系定义。

本轮改为使用关系名称作为选择键。点击关系边会展示：
- 关系名称；
- 源概念与目标概念；
- 基数（如有）；
- 对应字段；
- 关系校验规则。

点击概念节点仍会返回节点详情。展示值经过 HTML 转义。

## 建议验收方式

1. 执行 `make validate` 与 `make test`。
2. 启动 `python scripts/run_factory_portal.py`，在 Portal 的“本体发现”视图中检查正式本体关系图。
3. 点击一条关系边，确认详情面板显示关系名、源/目标、字段、基数和校验规则。
4. 点击一个概念节点，确认节点详情仍可正常显示。
5. 在“版本快照”创建两个快照并比较；在“依赖影响”选择一个概念查看已登记的消费者引用。
6. 对 GitHub/GitLab、PostgreSQL/MySQL 的真实连接，必须在隔离的集成环境中使用只读凭据进行独立验收。普通单元测试或 mock 不构成真实服务连通证明。
