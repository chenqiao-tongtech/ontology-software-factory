# 四阶段统一软件工厂平台实施报告

**版本日期：** 2026-10-29  
**项目：** `ontology-software-factory`  
**交付定位：** 基于既有工程成果扩展的本地可运行参考实现，不宣称已达到企业生产部署级别。

## 1. 实施结论

四阶段均已形成代码和可验证的端到端操作路径。统一门户默认运行在 `http://127.0.0.1:8770`，主界面提供平台总览、企业资产接入、本体图谱与候选治理、多智能体运行、质量与安全实验室、交付发布以及事件账本等工作区。

当前交付的重点是将既有本体、Workflow/Worker、质量门禁和配置交付能力编排到统一界面。外部平台凭据、企业身份认证、完整隔离测试床和真实生产部署仍属于后续生产化工作，不能把本地演示状态误当作这些能力已经完成。

## 2. 四阶段实施情况

### 阶段一：统一平台基础与共享契约

- 新增 `apps/factory-portal/index.html`，提供统一导航、深色高对比 UI、模块状态、事件记录和各工作区的交互入口。
- 新增 `scripts/run_factory_portal.py`，以 Python 标准库提供同源 HTTP API、对象 ID、事件记录和本地状态持久化。
- 通过 Source ID、Candidate ID、Run ID、Release ID、Event ID 关联关键对象。
- 默认只绑定回环地址；同源写请求检查；拒绝未经显式允许的非回环绑定。
- 本地状态保存于 `.local-portal/`，该目录已加入 `.gitignore`，可通过 `make clean-local` 清理。

**仍需生产化：** OIDC/SSO、RBAC/ABAC、多租户隔离、服务端数据库、不可篡改审计、速率限制、完整 CSRF/访问控制评审及 API 兼容策略。

### 阶段二：企业资产接入与本体工作台

- 支持本地代码/文档目录和 SQLite 数据库的只读元数据扫描。
- 可读取本地 Git 元数据（如果数据源本身是 Git 工作区），并支持 GitHub.com、GitLab.com HTTPS 仓库元数据 API。
- 私有 GitHub.com / GitLab.com 仓库可使用 `GITHUB_TOKEN` / `GITLAB_TOKEN` 环境变量；Token 不写入配置或响应。远端访问只在用户显式添加、同步或发起发现时发生。
- SQLite 使用只读连接读取表、视图和列信息；目录扫描限制文件类型和文件大小，并排除隐藏目录、依赖目录、密钥类文件。
- 以正式本体 JSON 绘制可交互 SVG 图谱，支持筛选、点选节点和查看定义/邻接关系。
- 从 Markdown 标题、Python 类/函数、JSON 键和 SQL 表声明中生成规则候选，并保留来源路径。
- 候选审查可形成批准提案或驳回记录；批准不会自动修改正式本体文件。

**仍需生产化：** OAuth/SSO、自托管 GitLab、Webhook/增量同步、远端文件正文安全获取、全文检索、语义推理、跨版本图谱 Diff 和大规模图布局。当前规则候选不是 LLM 本体学习结果。

### 阶段三：多智能体运行监控与质量/安全实验室

- 提供离线五阶段 Agent 运行示例，逐步记录状态和证据，并通过人工审批进入终态。
- 支持执行既有工程校验脚本和完整 unittest 套件，保存运行结果及日志摘要。
- 探测 Semgrep、Gitleaks、Trivy 是否可用；只有用户明确选择时才运行已安装扫描器。
- 将扫描器缺失、未执行、超时、完成但有发现、通过等状态分开显示，避免把“没运行”显示为安全通过。
- 写入门户事件账本，关联来源同步、本体候选、Agent 运行、质量运行和发布操作。

**仍需生产化：** 该门户新增 Agent 演示使用确定性 Fixture Runtime，不调用真实 LLM。真实 Agent 工作流仍通过已有 Agent Runtime/Workflow Console 运行，统一拓扑尚未订阅其持久化状态。测试床当前不是容器/微虚机隔离的任意代码执行环境，安全扫描范围也取决于真实接入的工具和配置。

### 阶段四：交付与发布中心

- 调用现有端到端配置交付流水线，生成 Kafka 风格的配置交付候选。
- 展示交付记录、manifest、文件 SHA-256、包体积和仅针对配置交付包的 SBOM。
- 审批动作要求记录审批人和原因；本地演练的执行人与审批人必须分离。
- 支持成功演练和模拟健康检查失败后的本地回退演练，结果标明 `realDeploymentPerformed=false`。

**仍需生产化：** 当前交付物不包含 Kafka 二进制；没有连接 OCI/通用制品仓库、Git 发布、CI/CD、Kubernetes/Argo CD、生产审批系统或真实部署集群。因此不能将此能力描述为真实生产发布。

## 4. 本地运行

```bash
python -m pip install -e .
make validate
make test
make portal
```

浏览器访问 `http://127.0.0.1:8770`。

可选私有远端仓库元数据接入：在启动前，于当前 shell 设置 `GITHUB_TOKEN` 或 `GITLAB_TOKEN`。不要把凭据写入源文件、数据源 JSON 或 issue。默认只允许公开服务 `github.com`、`gitlab.com` 的 HTTPS 仓库地址，不支持自托管 GitLab。

## 5. 安全与使用边界

- Portal 默认没有登录认证，只可在可信的本机环境使用。不要直接暴露到局域网或公网。
- 连接器仅读取元数据；但本地目录应选择已授权、适合扫描的位置，并评估文件名/路径是否包含敏感信息。
- 当前状态和事件记录保存在本地 JSON 中，不是不可篡改审计系统。
- Agent 运行状态、KPI 和图形中的示例数据应明确标注 Fixture/示例，不应向用户宣称为生产实时指标。
- 扫描器未安装或未执行，不得报告安全扫描通过；配置包 SBOM 不代表完整应用依赖或容器镜像 SBOM。
- 发布候选和回退演练属于本地配置包演示，不会部署真实软件。
